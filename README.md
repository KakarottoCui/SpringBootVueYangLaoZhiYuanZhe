老人信息管理、个性化服务管理、志愿者管理、活动管理、系统管理等

视频3在原系统基础上做的改动：

和购买者进行的需求确认如下（最终具体功能以视频演示为准！）

1、志愿者登录增加志愿者的服务时间维护，然后在接取服务那个页面，只能看到符合自己服务时间的服务项目，然后接取。
回答：是的。

2、志愿者能够维护自己的个性化服务，亲属账号登录可查看每个志愿者个性化服务。（老人登录账号要看吗？然后这个就是查看吗，需不需要对服务接取有影响。比如选了自己能做饭，就截不到打扫卫生这种）
回答：①现在系统是分为老人、亲属、志愿者和管理员四个端吗？老人和亲属应该是共用一个端，也就是说老人和亲属用的是同一个账号，可以直接改成亲属和老人一对多，即一个亲属账号下可以绑定多个老人的信息。不需要给老人单开账号。
②志愿者的意象对服务接取没有影响，只有意向时间对服务接取和查看有影响。

3、增加评价系统，老人和志愿者双向评价。（亲属发布的服务呢？现在的系统，亲属和老人似乎没关系，就是亲属也可以和志愿者双向评价）。然后增加一个评价报表，开放给所有人？
①亲属和老人的关系在第2项的①解释了。
②对的，评价这个部分我目前没什么设想（因为是导师提供给我的功能），或许可以在老人的个人服务模块和志愿者的接服务模块开一个子功能，显示已经整个系统里完成的所有人的服务和它们绑定的双向评价（只是设想，总之按导师的说法，评价是和单次服务绑定的）

4、志愿者这边增加个人的志愿时长统计，按月显示。管理员那边确定不要是吧。
回答：管理员端如果也有个这种可视化大屏就最好了，但显然我还没有设想。（可以显示整个服务器里的志愿时长统计？）总之能加最好。
